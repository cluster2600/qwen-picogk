# Corrective teaching corpus 003

This corpus contains **16 newly authored C# programs and 32 message rows**. Eight programs refuse to manufacture without named engineering evidence; eight construct precisely specified flat-ended cylindrical beams. Each answer is presented under the unchanged compact and development-generic headers already recorded in corrective corpus 002. The two styles share the same answer bytes. These are 16 programs, not 32 independent programs.

The programs and scenarios are synthetic. No held-out development task body, gold answer, captured model response, final task, imported scan, or proprietary engineering data was used. The existing export and zero-area-triangle filter boilerplate was reused from corrective corpus 001. The preceding corpora and evaluation files remain unchanged.

Every task overrides the generic report with its own exact three-key JSON contract. Keys vary by task. Values preserve the requested strings, Boolean authorization flag, and ordered array of missing evidence IDs. No extra evidence claim, nested qualification object, or process-status field is allowed.

- Refusals use managed C# only. They create no PicoGK context or geometry and never access the input argument. Junk, valid XYZ, empty, overflow JSON, malformed, nonfinite XYZ, and nonexistent input paths all yield the same requested refusal.
- Beams use the literal radii (0.55–1.07 mm) and endpoint vectors with `Lattice.AddBeam(..., false)`. They add no inferred features. An owned headless `Library` bounds native object lifetime. The same `Voxels` object supplies VDB and STL, and the filter removes exactly zero-area triangles.

`native-review-002/report.json` records **16/16 passing programs and 648 all-true Boolean checks**, including native exit zero, exact JSON types and keys, closed oriented nondegenerate STL, independent cylinder volume and world bounds, and thirteen radius/end-cap probes against both VDB and direct STL triangle parity. The worst analytic-volume error is 5.24% with 0.2 mm voxel sampling; the fixed tolerance is 10%. Alternate beam inputs preserve exact STL bytes and the same VDB volume, bounds and occupancy.

`native-review-001` is retained. Its beam programs passed all geometric and report checks but the checker mistakenly required byte-identical VDB serializations. VDB file identifiers change between exports. The corrected checker compares the actual VDB solid natively and retains exact repeated STL-byte comparison. No teacher changed to resolve that checker defect.

`fault-review-001` separately runs two deliberately incorrect beam programs, with a halved radius or rounded caps. These programs are not in the corpus. Native occupancy and independent STL probes reject both faults.

The checked-in scientific bibliography is copied unchanged from the previously verified corpus. Curless–Levoy range integration does not establish a missing engineering interface from unsigned points. Cloots' support experiments are process specific; this coupon is not a support-release strategy. Mercelis–Kruth residual-stress principles are not solved by a diameter rule or closed mesh. Validation establishes software and geometry behavior only; manufacturing remains unauthorized.

Native validation uses the existing trusted evaluator, pinned .NET/PicoGK runtime, candidate sandbox and independent STL parity checker. It performs no model loading, GPU inference, training, or GitHub publication. CPU tokenizer receipts and downstream mixture provenance are recorded separately before any training course is registered.
